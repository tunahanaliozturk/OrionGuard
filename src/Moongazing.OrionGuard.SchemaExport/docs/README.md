# OrionGuard.SchemaExport

Exports the validation rules you already declared on a model for [OrionGuard](https://github.com/tunahanaliozturk/OrionGuard) as a JSON Schema document or a TypeScript interface, so the frontend consumes the rules instead of a hand-written copy of them.

## Install

```bash
dotnet add package OrionGuard.SchemaExport
```

The core `OrionGuard` package is installed as a dependency. Nothing else is: the exporters use `System.Text.Json` only.

## Quick start

```csharp
using Moongazing.OrionGuard.Attributes;
using Moongazing.OrionGuard.SchemaExport;

public sealed class CreateUserRequest
{
    [NotNull, Email] public string Email { get; set; } = "";
    [Length(8, 100)] public string Password { get; set; } = "";
    [Range(13, 120)] public int Age { get; set; }
    [Positive] public decimal Budget { get; set; }
    public Uri? Website { get; set; }
}

File.WriteAllText("create-user.schema.json", JsonSchemaExporter.Export<CreateUserRequest>());
File.WriteAllText("create-user.ts", TypeScriptExporter.Export<CreateUserRequest>());
```

`JsonSchemaExporter.Export<T>()` returns an indented JSON Schema draft 2020-12 document. `JsonSchemaExporter.Export<T>(Utf8JsonWriter)` writes the same object to a writer you own, for streaming it or nesting it inside a larger document.

`TypeScriptExporter.Export<T>()` returns the interface declarations as text, with `\n` line endings on every platform so the file is byte-identical wherever it is generated. It emits **types only**: the constraints are written as doc comments, never as runtime checks.

### Emitted JSON Schema

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "title": "CreateUserRequest",
  "type": "object",
  "properties": {
    "email": { "type": "string", "format": "email" },
    "password": { "type": "string", "minLength": 8, "maxLength": 100 },
    "age": { "type": "integer", "minimum": 13, "maximum": 120 },
    "budget": { "type": "number", "exclusiveMinimum": 0 },
    "website": { "type": ["string", "null"], "format": "uri" }
  },
  "required": ["email"]
}
```

### Emitted TypeScript

```ts
// Generated by OrionGuard.SchemaExport from YourApp.CreateUserRequest.
// Types only: the constraints below are documented here, not enforced here.

export interface CreateUserRequest {
  /** required; format: email */
  email: string;
  /** 8 to 100 characters */
  password?: string;
  /** between 13 and 120 */
  age?: number;
  /** greater than 0 */
  budget?: number;
  /** format: uri */
  website?: string | null;
}
```

## What the artifacts do not cover

This is the point of the package: what cannot be exported is reported, never dropped.

A rule the exporters cannot express is listed under `x-orionguard-unsupported` on the schema that declares the member, and gets a `// not enforced here:` comment above the member in the TypeScript:

```csharp
public sealed class PasswordChange
{
    [NotNull, Length(8, 64)] public string Password { get; set; } = "";
    [MatchesPassword] public string Confirmation { get; set; } = "";   // your own ValidationAttribute
}
```

```json
"x-orionguard-unsupported": [
  { "member": "confirmation", "rule": "MatchesPasswordAttribute" }
]
```

```ts
  // not enforced here: MatchesPasswordAttribute
  confirmation?: string;
```

One gap the artifacts cannot even report: rules registered on an `AbstractValidator<T>`, or built with `Validate.For` / `Validate.Nested` / `Validate.CrossProperties`, are C# delegates. Reflection cannot read a delegate's body, so those rules are invisible to the exporters and no trace of them reaches the artifact. If a rule must reach the frontend, declare it as an attribute.

## Rule mapping

| Attribute | JSON Schema | TypeScript comment |
| --- | --- | --- |
| `[NotNull]` | adds the member to `required` | `required` |
| `[NotEmpty]` | adds the member to `required`, plus `minLength: 1` (`minItems: 1` on a collection) | `required; at least 1 character` |
| `[Length(min, max)]` | `minLength`, `maxLength` (`minItems`, `maxItems` on a collection) | `min to max characters` |
| `[Range(min, max)]` | `minimum`, `maximum` | `between min and max` |
| `[Regex(pattern)]` | `pattern` | `pattern: ...` |
| `[Email]` | `format: email` | `format: email` |
| `[Positive]` | `exclusiveMinimum: 0` (the numeric form used by JSON Schema 2020-12) | `greater than 0` |
| any other `ValidationAttribute` | `x-orionguard-unsupported` | `// not enforced here: ...` |

`[NotEmpty]` rejects null as well as the empty value, so it makes a member required on its own. Attributes combine rather than overwrite: two `[Length]` rules produce the bounds that satisfy both.

## Type mapping

| CLR | JSON Schema | TypeScript |
| --- | --- | --- |
| `string`, `char` | `string` | `string` |
| integral types | `integer` | `number` |
| `float`, `double`, `decimal` | `number` | `number` |
| `bool` | `boolean` | `boolean` |
| `Guid` | `string`, `format: uuid` | `string` |
| `Uri` | `string`, `format: uri` | `string` |
| `DateTime`, `DateTimeOffset` | `string`, `format: date-time` | `string` |
| `DateOnly` / `TimeOnly` | `string`, `format: date` / `time` | `string` |
| `TimeSpan` | `string` | `string` |
| enum | `string` plus an `enum` list of the member names | a union of the member names |
| `IEnumerable<T>`, `T[]` | `array` with `items` | `T[]` |
| dictionary | `object` | `Record<string, unknown>` |
| any other class, record, or struct | `$ref` into `$defs` | its own `export interface` |
| `object` | unconstrained | `unknown` |

OrionGuard has no URL attribute, so a `Uri` member is the only way the exporters know a string holds a URL.

## Behaviour details

- Members are the public instance properties with a getter, the same surface `AttributeValidator` and the Swagger schema filter validate. Indexers and `[JsonIgnore]` members are skipped.
- The serialized name is `[JsonPropertyName]` when present, otherwise the camelCase form of the property name.
- A member is **required** only when an OrionGuard rule requires it. A non-nullable CLR type on its own does not: it removes the `null` branch from the type, but leaves the member optional (`?`) in TypeScript and out of the `required` list.
- A nullable member gets `"type": ["x", "null"]`; a nullable nested type gets an `anyOf` with a `{"type": "null"}` branch. A property in an assembly compiled without nullable reference types is treated as nullable, because nothing there rules null out.
- Enums are exported **by name**, which is what `JsonStringEnumConverter` writes. A payload that serializes enums as numbers will not match the schema.
- Nested types are emitted once under `$defs` and referenced. A type that references itself, directly or through a cycle, points back at the document root (`"$ref": "#"`).
- Two nested types with the same short name would collide in `$defs`, so the second one is published under its namespace-qualified name instead.

## Trimming and NativeAOT

Both `Export<T>` methods are marked `[RequiresUnreferencedCode]`: they walk the exported type's public properties, and the types of those properties, with reflection. Under trimming or NativeAOT, root the exported types (for example with `DynamicDependency`) or the artifact will be missing members that were trimmed away.
